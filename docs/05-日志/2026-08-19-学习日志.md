## 今日完成

### 阶段 2 第 1 步：电角度获取模块实现与验证

在 `user/` 目录下新建 `encoder.c/h`，实现从 AS5600 原始值到 Park 变换可用 sin/cos 的完整数据链路。

#### 数据流

```
AS5600 raw (12-bit 0~4095)
  → 机械角度 θ_m = raw × 360/4096 (度)
  → 电角度 θ_e = (θ_m − offset) × 7, mod 360 (度)
  → 弧度 = θ_e × π/180
  → sin(θ_e), cos(θ_e) 用于 Park 变换
```

#### 接口设计

| 函数 | 返回 | 用途 |
|---|---|---|
| `Encoder_SetOffset(float)` | void | 设置零点偏移（机械角度空间，待 SVPWM 实现后校准） |
| `Encoder_GetMechAngle(void)` | float [0,360) | 机械角度 |
| `Encoder_GetElecAngle(void)` | float [0,360) | 电角度 |
| `Encoder_GetElecRad(void)` | float [0,2π) | 电角度弧度 |
| `Encoder_GetSinCos(float*, float*)` | void | 同时返回 sin/cos，Park 变换用 |

#### 实现中的问题与修复

1. **电角度公式错误**：初版写成 `mech × P − offset`，量纲不匹配（offset 是机械角度空间，乘 P 后再减在电角度空间）。修正为 `(mech − offset) × P`，先在机械空间减偏移，再乘极对数转电角度空间。数字验证确认修复正确。

2. **M_PI 可用性**：armclang 工具链下 `math.h` 的 `M_PI` 可用性不确定，用 `#ifndef M_PI` 保护定义 fallback。

3. **MX_MotorControl_Init() 临时注释**：为规避 ADR-008（MCSDK `while(1)` 执行缓慢），在 main.c 注释掉 `MX_MotorControl_Init()` 调用，跳过 `MCboot()`。I2C1 和 USART2 初始化独立不受影响，电角度验证无需电机控制运行。

4. **USART 波特率调整**：从 921600 降至 115200，提高串口通信稳定性。

#### 验证结果

串口每 50ms 打印 θm、θe、sin、cos，手动慢转电机一圈：
- θm 在 0~360 变化 **1 次**（机械一圈）
- θe 在 0~360 变化 **7 次**（电角度 = θm × 7 mod 360）
- sin/cos 振荡 7 个周期，与 θe 一致

抽样验证 `θe = θm × 7 mod 360` 关系全部成立（误差来自 Printf 参数中 3 次独立 I2C 读取的角度微小差异）。

## 反思

- 电角度公式错误暴露了一个易混淆点：offset 的空间归属（机械角度 vs 电角度）。先减后乘还是先乘后减，取决于 offset 定义在哪个空间。明确"offset 是 AS5600 在电角度=0 时的机械读数"后，公式应为先减（机械空间）后乘（转电角度空间）。
- Printf 参数中调用有副作用的函数（I2C 读取）是不好的实践，求值顺序未定义且多次读取。调试阶段可接受，闭环时需改为"读一次返回全部值"的接口。
- AGENTS.md 约定的 ADR-008 临时绕过方案（注释 MX_MotorControl_Init）在本次验证中确认有效，while(1) 不再执行缓慢。
