### 第 3 步：SVPWM 实现与数值验证

在 `user/` 目录下新建 `svpwm.c/h`，实现 `Svpwm_Calc(v_alpha, v_beta, vdc, Ts, ARR, &ccr_a, &ccr_b, &ccr_c)`，输出直接给 TIM1 的 CCR。

#### 实现步骤

| 步 | 内容 | 说明 |
|---|---|---|
| 1 | X/Y/Z 计算 | `X = vβ`，`Y = (√3·vα − vβ)/2`，`Z = (−√3·vα − vβ)/2` |
| 2 | 扇区判断 | `A/B/C` 由 X/Y/Z 是否 > 0 得到，`N = 4C + 2B + A`，查表得扇区 1~6 |
| 3 | 作用时间 | `K = √3·Ts/vdc`，按扇区查表得 `TX/TY` |
| 4 | 过调制限幅 | `TX+TY > Ts` 时按比例缩放到 `Ts`，`T0 = Ts − TX − TY` |
| 5 | 比较点 | `Ta' = T0/4`，`Tb' = Ta' + TX/2`，`Tc' = Tb' + TY/2`，按扇区分配到 A/B/C 相 |
| 6 | CCR 映射 | `CCR_x = (Ts − 2·Cmp_x)·ARR/Ts`，四舍五入后钳位到 `[0, ARR]` |

`Ts` 归一化为 1.0，`ARR` 运行时取 `htim1.Init.Period`（不硬编码，换 PWM 频率后自动跟随）。

#### 验证方法（重构不变式）

不读内部中间量，而是从输出的 CCR 反推：`占空比 → 减均值去共模 → Clarke 变换 → 应与 1.5·vα/vdc 相等`，用 `err` 作为唯一通过判据。好处是判据与实现解耦，扇区表/作用时间表/相序表任一处出错都会让 `err` 变大。

主循环改为 15° 步进扫描 0°~345°（24 点后回绕），每 200ms 打印一行，一行对应一个电角度。

#### 验证结果

- **24 个角度点 `err` 全部为 `0.000`**（打印精度 `%5.3f`，即 `err < 5×10⁻⁴`）✅
- 手算复核 θ=15°/120°/180° 三点，CCR 与公式计算完全一致 ✅
- θ=30°/90°/… 处 CCR 触及 2625（满）与 0（零），符合 M=1.0 线性区上限的预期 ✅
- 六个扇区全部扫到，CCR 连续无跳变 ✅

### 附带 1：SVPWM 接口简化与复测

写 `motor_control.c` 时发现 `Svpwm_Calc()` 把硬件细节包进来了——它接受 `Ts`、`ARR`，直接吐 CCR。SVPWM 是纯数学模块，不该知道 TIM1 的 ARR，于是改成：

```c
/* 输入 v_alpha/v_beta/vdc（V），输出三相高侧占空比 0.0~1.0，内部时间单位：一个 PWM 周期 = 1 */
void Svpwm_Calc(float v_alpha, float v_beta, float vdc, float *da, float *db, float *dc);
```

占空比→CCR 的换算下移到 `motor_control.c`（`CCR = duty × htim1.Init.Period`）。算法本体一字未动。

复测 24 点：`err` 从 `1.9×10⁻⁴` 降到 `5.96×10⁻⁸ ~ 4.79×10⁻⁷`，**掉了约三个数量级**——正好是去掉 CCR 取整量化的效果，现在的残差是 float32 单精度极限，不是算法误差。占空比与初稿 CCR 逐点对应（`duty × 2625 = 旧 CCR`），证明简化是数学等价而非重写。

### 第 3 步（上板）：开环强拖旋转与编码器方向标定

`main.c` 写成两阶段状态机：先固定电角度对齐 2 s（`uq = 0.5 V`），再匀速旋转（`uq = 0.8 V`，`fe` 从 5 Hz 试到 0.5 Hz）。角度按真实时间积分——打印是阻塞的，固定步长会被它拉低实际频率。串口输出全改 ASCII，并接入 AS5600 读回电角度，打印 `cmd / enc_e / d`。

三轮实验：

1. **看波形**（未接编码器）：示波器看到 16 kHz 方波、占空比随指令变化。`CCER = 0x0111` —— 只有 CC1E/CC2E/CC3E 为 1，**实测确认 CH1N/2N/3N 与 CH4 都没使能**，IHM07M1 果然是「3 路 PWM + 3 路 EN」驱动方式，之前关于 CHxN 是否引出的疑问到此有了定论。
2. **接编码器**：`st:0` 阶段 `enc_e` 恒定，对齐生效；但进入旋转后发现 **`cmd` 每行 −90° 而 `enc_e` 每行 +88°** —— 方向相反。
3. **标定后复测**：`ENCODER_DIR = -1`，`enc_e` 与 `cmd` 同向，`d` 稳定在 −121° 附近。

**核心判据是丢步检查**：取 `cmd ≈ 271.6°` 这个相位点，12 个电气圈里逐圈读 `enc_e`，读数在 ±5° 内振荡、无单调漂移；11 个电气圈（正好 3960° 指令旋转）净差 −0.9°，**累计滞后 0.023%，判定无丢步**。那 ±5° 抖动不是噪声——编码器电角度分辨率是 0.615°，观测抖动是它的约 8 倍，是转子真的在同步位置附近摆。

详见 `docs/03-实验/20261011-开环旋转与编码器方向标定.md`。

## 反思

- **验证判据的设计比实现本身更值得琢磨。** 这次没有去逐个 assert 内部变量，而是构造了一个「输入 → 输出 → 反推回输入」的闭合环路（重构不变式）。好处：判据是黑盒的，不依赖对实现的假设；坏处：它对某些量天生不敏感——比如 `VDC` 和 `M` 的绝对标度（`v_alpha ∝ VDC` 与 `K ∝ 1/vdc` 互相抵消），所以它证明不了「电压单位/标度是对的」。用判据时要清楚它测不到什么。
- **打印列不等于算法内部状态。** `sec` 列是从扫描角 `(int)(θ/60)+1` 反推的，实测发现 θ=0°/120°/240° 上与内部扇区号差 1（因为 `>0` 是严格比较，边界矢量被归给相邻扇区）。两扇区在边界等效、输出相同，所以不影响正确性——但这是「数值正确」和「内部状态可观测」的差别，做波形级调试时容易踩。
- **`err = 0.000` 不能理解成「误差真的为 0」。** 反算后残差约 1.9×10⁻⁴，正好是 3 个 CCR 各自取整到整数引入的量化噪声量级，和理论上限 4.4×10⁻⁴ 一致。把「量化噪声量级」和「算法误差」分开，才不会在下一步碰到真实误差时误判。
- **过调制限幅这次没被验证到。** M=1.0 时 `TX+TY ≤ Ts` 恒成立，`sum > Ts` 分支根本没执行。下步把 M 提到 1.15 补测——那时 `err` 非零是**预期**的（超出线性区本来就跟随不上），要看的是 CCR 是否仍被正确钳位。
- **"传 `ARR` 进去"这种设计错误，写调用方的时候才会暴露。** 写 `main.c` 和 `motor_control.c` 时才发现：算 CCR 需要 `ARR`，而 `ARR` 属于定时器配置，属于硬件层。于是同一个值要在两个地方都拿到，SVPWM 模块也被绑死在 TIM1 上。把 `ARR` 从形参里去掉、只输出占空比之后，两个调用方各自用 `htim1.Init.Period` 换算即可，模块回到纯数学。**验证方法还是"看调用方写得顺不顺"**——调用方别扭，往往是接口分层错了。
- **`err` 降了三个数量级，但结论没变。** 去掉取整量化后 `err` 从 `1.9×10⁻⁴` 到 `1e-7`，可算法一个字没改。这说明原来那 1.9×10⁻⁴ 从头到尾都不是"误差"而是"分辨率"——判断一个数是误差还是分辨率，得看它跟实现细节（这里是整数取整）绑不绑得死。
- **数值再精确也测不出符号错误。** SVPWM 的 `err` 是 1e-7，波形、占空比、手算全对，但编码器方向反了——这个错误在数值层完全不可见，只有让电机真转起来才暴露。而且它的症状（`d` 在 −58 和 +124 之间跳 180°）第一眼像"数据是坏的"，不像"符号是反的"。**物理层的验证不能省。**
- **判据要能证伪，不能靠"看着在转"。** 验证"无丢步"如果只用单次采样，±5° 的机械抖动和 0.3%/圈的丢步长得一模一样。做法是取**同一个指令相位点**在多圈里重复读——丢步会累积成单调漂移，抖动只在原地摆。11 圈净差 0.9°，这个结论比"看起来在转"扎实得多。
- **抖动和分辨率要分开看。** 观测到的 ±5° 到底是测量噪声还是真实的机械摆动？查一下编码器分辨率：12 位、机械 0.088°、乘 7 后电气 0.615°。抖动是它的 8 倍，所以不是量化产生的，是转子真的在同步位置附近摆——开环没有电流环，齿槽力矩与摩擦轮流拉扯它。**一个数字是噪声还是现象，得拿去和系统的分辨率底噪比。**
