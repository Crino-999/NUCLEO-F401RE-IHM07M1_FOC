# 实验记录：AS5600 编码器 I2C 通信验证

> 状态：已验证 | 日期：2026-08-18 | 关联：学习总计划-阶段1、ADR-007 AS5600 编码器接入 | 硬件：NUCLEO-F401RE + X-NUCLEO-IHM07M1

## 一、实验目的

验收阶段 1 的 AS5600 编码器接入任务（ADR-007 Step 1）：
- 硬件接线：将 AS5600 磁编码器通过 I2C 接入 NUCLEO-F401RE
- 软件驱动：移植 AS5600 驱动代码，配置 I2C1 外设
- 通信验证：通过串口打印确认角度数据随电机轴转动连续变化

## 二、硬件接线

### 2.1 引脚选择依据

从硬件笔记（`docs/02-笔记/开发板硬件/`）引脚占用统计确认：GPIOB 仅 PB1 被占用（电位器），PB8/PB9 空闲且未被 IHM07M1 使用。

| AS5600 模块 P1 | NUCLEO-F401RE 引脚 | Morpho 位置 | 说明 |
|---|---|---|---|
| VCC | 3.3V | CN7 pin 16（+3.3V） | AS5600 模块 R6 默认在位，只能接 3.3V |
| GND | GND | CN10 pin 9 | 与 I2C 引脚同排针，接线方便 |
| SCL | PB8 | CN10 pin 3 | I2C1_SCL（AF4） |
| SDA | PB9 | CN10 pin 5 | I2C1_SDA（AF4） |

### 2.2 AS5600 模块供电注意事项

AS5600 模块（M创动工坊）板上 R6（0Ω）跳线默认焊接在位，将 VCC 直接连到 3.3V 轨。**R6 在位时严禁接入 5V**——会形成 5V→3.3V 轨直接短路，可能烧毁 AS5600 芯片和 MCU。如需 5V 供电，须先拆掉 R6。

本次实验全程使用 3.3V 供电，未修改 R6。

## 四、AS5600 驱动代码

### 4.1 文件结构

| 文件 | 说明 |
|---|---|
| `NUCLEO-F401RE/user/as5600.h` | AS5600 寄存器定义 + 函数声明 |
| `NUCLEO-F401RE/user/as5600.c` | I2C 读取实现（从旧工程移植） |
| `NUCLEO-F401RE/Src/i2c.c` | CubeMX 生成的 I2C1 初始化 |

### 4.2 关键实现

- **I2C 地址**：AS5600 7-bit 地址 0x36，HAL 库需左移 1 位 → `0x6C`
- **角度寄存器**：`RAW_ANGLE_H`(0x0C) + `RAW_ANGLE_L`(0x0D)，连续读 2 字节
- **HAL 调用**：`HAL_I2C_Mem_Read()`，内部自动处理 Start→写寄存器地址→Restart→读数据→Stop
- **分辨率**：12-bit（0~4095），对应 0~360°，转换系数 `360.0/4096.0`
- **超时**：100ms（足够 I2C 一次读取约 0.5ms）

### 4.3 串口打印辅助函数

在 `usart.c` 中实现了 `Printf()` 函数，基于 `vsnprintf` + `HAL_UART_Transmit` 阻塞发送，256 字节静态缓冲区。不依赖 MicroLIB，无需重定向 `fputc`。

## 五、主循环调用时机

### 5.1 MCSDK 三层任务架构

| 层级 | 频率 | 触发 | 内容 | I2C 轮询可行性 |
|---|---|---|---|---|
| 高频任务 | 16kHz | ADC 注入中断 | Clarke→Park→PI→SVPWM | ❌ 100ms 超时卡死中断 |
| 中频任务 | 1kHz | SysTick | 速度环 PI、状态机 | ❌ 阻塞 SysTick |
| 主循环 | 不固定 | while(1) | 低速任务 | ✅ 可行，需降频 |

### 5.2 采用方案

主循环 + `HAL_GetTick()` 降频，每 50ms 读取一次：

```c
static uint32_t lastTick = 0;
if (HAL_GetTick() - lastTick >= 50)
{
    lastTick = HAL_GetTick();
    rawAngle = AS5600_ReadRawAngle();
    AS5600_GetAngle(&angle);
    Printf("Raw: %4d  Angle: %6.1f\r\n", rawAngle, angle);
}
```

50ms（20Hz）对肉眼观察电机轴转动足够，I2C 轮询阻塞约 0.5ms，对主循环影响可忽略。

## 六、MCSDK while(1) 执行缓慢问题（调试副发现，2026-10-07 归档）

> **归档状态（2026-10-07）**：该问题在当前工程配置下**已不复现**，从活跃问题清单移除（ADR-008 → ❌ 已推翻，被 ADR-009 替代）。原因是 ADR-009 生效后 `main.c` 不再调用 `MX_MotorControl_Init()`、`MCboot()` 不启动，偏移校准所在的调用路径不执行。**这是「绕过」而非「修复」**——根因始终未确认；本节下面的「根因」是 2026-08-18 的原始判断，2026-10-07 的源码核对显示其与代码实际不符，详见 `docs/01-计划/项目状态与Codex协作交接.md` 5.5 节「2026-10-07 源码核对备注」。

### 6.1 现象

AS5600 串口打印间隔异常长（约 1 分钟一次），CPU 负载极高。排查后定位到 MCSDK 初始化阶段的电流校准函数。

### 6.2 根因（2026-08-18 原始判断，2026-10-07 核对存疑）

`R3_1_CurrentReadingCalibration()`（`r3_1_f4xx_pwm_curr_fdbk.c` 约 203 行）在 `__disable_irq()` 禁用全部中断后，调用 `waitForPolarizationEnd()` 等待 ADC 中断递增 `PolarizationCounter`——当时判断为「中断已被禁用，计数器永不递增，程序永久死锁」。

死锁发生在 SysTick 中断上下文中（`MCboot → TSK_MediumFrequencyTaskM1 → PWMC_CurrentReadingCalibr → R3_1_CurrentReadingCalibration`），导致 CPU 100% 占用，主循环极少有机会执行。

> ⚠️ 上述链条与定性**已于 2026-10-07 核对否定**（`__disable_irq()` 后紧接 `__enable_irq()`，等待期间中断是开的；`MCboot()` 不调用中频任务；等待循环有约 2 ms 超时）。原文保留以便追溯，勿作为结论引用。

### 6.3 临时绕过

调试 AS5600 等非电机功能时，在 `motorcontrol.c` 中跳过 `MCboot()` 调用。此问题登记为 ADR-008，待电机控制调试阶段再正式解决。（后由 ADR-009 取代：`main.c` 中直接注释掉 `MX_MotorControl_Init()`，`MCboot()` 不再启动）

### 6.4 验证结果

绕过 `MCboot()` 后，串口打印恢复正常 50ms 间隔，角度值随电机轴转动连续变化（0~4095），AS5600 通信验证通过。
