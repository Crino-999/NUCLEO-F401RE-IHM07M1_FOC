# 实验记录：MC Workbench 参数改动与级联重算验证

> 状态：已验证 | 日期：2026-08-17~18 | 关联：学习总计划-阶段1、验收项 M1 工具链闭环 | 硬件：NUCLEO-F401RE + X-NUCLEO-IHM07M1

## 一、实验目的

验收阶段 1 核心要求："能独立完成**改参数→重新生成→部署→验证响应**全流程"。具体以改动 PWM 频率为载体，验证 MC Workbench 的级联重算机制——改一个源参数，生成器自动重算多少派生参数，以及这些变化如何体现在电机实际行为上。

## 三、实验过程中的故障排查：电机无法切闭环

### 3.1 现象

重新接线后，电机开环强拖有效（Phase1/2 能转），但准备切到闭环时报**转速反馈故障**，无法稳定启动。

### 3.2 排查过程

| 步骤 | 假设 | 验证 | 结论 |
|---|---|---|---|
| 1 | 电机相序接反（U/V/W 两相交换） | 对照接线图确认无误；交换两根线序重测，现象不变 | 排除 |
| 2 | 代码参数被改过 | `git log` 查参数文件历史：只在初始提交 `d432045` 出现，之后 12 次提交全是 `docs:`；`git diff` 工作区零修改 | 排除 |
| 3 | 两板 Morpho 排针接触不良 | （未及深入检查） | — |
| 4 | 电位器位置问题 | 电位器被拧到底（对应最低转速） | **命中** |

### 3.3 根因：电位器最低转速与观测器下限的配置矛盾

| 参数 | 值 | 来源 |
|---|---|---|
| `POTENTIOMETER_MIN_SPEED_M1` | ≈250 rpm（`MAX_APPLICATION_SPEED_UNIT/10`） | `drive_parameters.h` |
| `OBS_MINIMUM_SPEED_RPM` | 901 rpm | `drive_parameters.h` |

电位器拧到底 = 目标转速 250 rpm，但观测器在 901 rpm 以下无法估算转子位置（反电动势太弱，STO 失锁）。开环强拖到 Phase2 的 1001 rpm（>901）看起来"开环有效"，切闭环后速度环跟随电位器目标 250 rpm，转速迅速跌破 901 → 观测器失锁 → 报转速反馈故障。

**配置上的隐藏矛盾**：电位器允许的最低转速（250）低于观测器能工作的最低转速（901），拧到底必然闭环失败。

### 3.4 纠正认知

此前以为"电位器和 PC13 按键无效、只能用 Pilot 启动"——错误。电位器有效，只是位置导致转速过低，看起来像"没功能"。Pilot 之所以"能启动"，是因为它下发的是高于 901 rpm 的转速指令。

**教训**：MCSDK 参数间的依赖约束不是显式的，"电位器下限 < 观测器下限"这种矛盾不会在配置时报错，只在运行时以故障形式暴露。

## 四、PWM 频率 16kHz→8kHz 实操

### 4.1 操作步骤

1. 打开 `NUCLEO-F401RE.stwb6`，在 Workbench 中将 PWM Frequency 从 16000 改为 8000
2. 重新生成代码
3. 编译并烧录到控制板
4. 用 Pilot 启动电机，验证运转

### 4.2 级联重算对照（预测 vs 实际）

改 `PWM_FREQUENCY` 一个源参数后，对比重新生成前后的参数变化：

| 参数 | 16kHz | 8kHz | 派生机制 |
|---|---|---|---|
| `PWM_FREQUENCY` | 16000 | 8000 | 源参数（用户改） |
| `PWM_PERIOD_CYCLES` | 5250 | 10500 | 公式：`ADV_TIM_CLK/PWM_FREQ`，自动翻倍 |
| `ISR_FREQUENCY_HZ` | 16k | 8k | 公式：`PWM_FREQ/REG_RATE`，自动减半 |
| `TF_REGULATION_RATE` | 16 | 8 | 同上，影响 C1/C3/C5 |
| `C1`（观测器） | ~4083 | ~8166 | 公式：`(F1·Rs)/(Ls·TF_RATE)`，翻倍 |
| `GAIN1` | -21509 | -18442 | **Workbench 重算**（非公式派生） |
| `GAIN2` | 26133 | 28139 | **Workbench 重算** |
| `PLL_KP_GAIN` | 582 | 1165 | **Workbench 重算**，约 2 倍 |
| `PLL_KI_GAIN` | 26 | 103 | **Workbench 重算**，约 4 倍 |
| `F2` | 8192 | 16384 | **Workbench 重算**（缩放因子） |
| `PID_TORQUE_KP` | 2627 | 2627 | 值未变 |
| `PID_TORQUE_KI` | 2622 | 2622 | 值未变 |
| `TF_KIDIV` | 4096 | 2048 | **减半**，补偿频率减半 |

### 4.3 两个超出预期的发现

**发现 A：观测器增益 GAIN1/GAIN2 和 PLL 增益被 Workbench 重新整定**

原以为 GAIN1/GAIN2/PLL 增益是固定常数，实际 Workbench 的 autoObserver 在重新生成时根据新频率重新计算了它们。级联影响比"公式自动派生"更深——Workbench 会主动重新整定观测器/PLL 参数适配新频率。

**发现 B：PID 增益值本身没变，靠 divisor 补偿**

`PID_TORQUE_KP/KI` 数值未变，但 `TF_KIDIV` 从 4096 减半到 2048。等效积分作用 = `KI/TF_KIDIV`，divisor 减半 = 等效积分作用翻倍，正好补偿电流环执行率减半。Workbench 用"动 divisor 不动增益值"的方式适配频率变化，保持增益数值的稳定性。

## 五、三个观察发现的技术分析

### 5.1 嗡鸣声更尖锐

8kHz 处于人耳可闻中高频段（最敏感区 2~4kHz），听感尖锐刺耳；16kHz 接近可闻上限，成年人高频听力衰减，听感反而微弱低沉。所以"8kHz 更尖锐"符合声学，证明 **PWM 频率改动确实生效**。

### 5.2 欠压故障 + 启动电流 1.426A

- 启动序列 Phase1/2 电流目标均为 2A（`PHASE1_FINAL_CURRENT_A=2`），`IQMAX_A=2`
- 实测启动峰值 1.426A，在 2A 限幅内，属正常启动电流
- 可调电源限流 1A < 1.426A → 电源被拉垮 → 母线电压跌破 `UD_VOLTAGE_THRESHOLD_V=8.0V` → 欠压故障
- **级联影响**：8kHz 电流环执行率减半，电流响应变慢，启动电流峰值可能比 16kHz 更高/持续更久 → 更易触发电源限流
- 对策：电源限流调到 ≥2A（额定电流），避免启动瞬态触发欠压

### 5.3 d 轴电流高速时闪过 -0.01/-0.02A

`Id` 应 = 0（SM-PMSM 最大转矩电流比策略）。-0.01~-0.02A 是极小值（额定 2A 的 0.5%~1%），高速时偶尔闪过，最可能为两因素叠加：

1. **观测器高速域角度小误差**：8kHz 观测器带宽降（`GAIN1/GAIN2` 重算正是为补偿），但高速域反电动势强、估算角度仍有偏差 → Park 变换后 Id 拗不完全为 0 → 留下小残差
2. **ADC 量化噪声底**：-0.01A 在 2A 量程是 0.5%，接近 ADC 噪声底

非故障。改回 16kHz 此现象应减弱——可作为对照实验验证"PWM 频率→观测器精度"级联。弱磁（FW）在 -0.01A 这么小的量级不像是主动弱磁介入。

## 六、收获

1. **走通工具链闭环**：独立完成"改参数→重新生成→部署→验证响应"全流程，达成阶段 1 验收项 M1
2. **理解级联重算**：改一个源参数，生成器自动重算 4 层派生参数（定时器周期→电流环执行率→观测器系数→PID divisor 补偿），且 Workbench 会主动重新整定观测器/PLL 增益
3. **掌握 MCSDK 参数间的隐藏约束**：电位器下限与观测器下限的矛盾，揭示了配置项依赖关系不显式报错的问题
4. **三个发现验证级联影响的实际表现**：声学（频率生效）、欠压（带宽→启动电流）、d 轴残差（观测器精度）
5. **额定转速是观测器整定输入**：改额定转速会级联重算观测器增益（GAIN2/PLL/C3），和电机物理特性不匹配导致启动失败。要突破转速上限应靠弱磁+过调制，不是改额定转速
6. **过调制有适用区域**：低速开过调制会震动顿挫（调制比<<1 时误激活），设计用于高速弱磁区。16kHz 是干净观察过调制控制影响的场（32kHz 被 CPU 边界掩盖）

## 八、其他参数实验

### 8.1 实验二：PWM 频率 32kHz（频率提升的反向问题）

**实验条件**：将 PWM 频率从 16kHz 提升到 32kHz，其余参数不变。用 Pilot 启动并逐步提升转速。

**Pilot 观测数据**（稳态 1950 rpm 时）：

| 项目 | 值 |
|---|---|
| CPU 负载率 | 55.2%（min 49.0 / max 68.1） |
| 转速 | 1950 rpm（参考 1980 rpm） |
| 母线电压 | 12 V |
| 功率 | 0.4 W |
| Id | -0.11 A（弱磁方向） |
| Iq | 0.07 A |
| 启用功能 | 弱磁、前馈、母线电压采样、温度采样、MCU 负载监控 |

**三个现象**：

1. **CPU 负载明显变高**（55.2%）
2. **转速无法快速提升**，能不触发报警停转的转速约 **2000 rpm**
3. **接近边界转速时失稳**：Id 绝对值明显变大（至约 0.34A），功率提升到接近 4W，电机抖动（速度时快时慢），扭矩冲击底座导致电机整体移动

**根因分析（因果链）**：

```
PWM 频率 32kHz
  ├─ 电流环执行率翻倍（32k 次/秒）
  │    → CPU 负载 55.2%（中断计算量不变，频率翻倍）
  │
  ├─ PWM 周期减半（31.25μs）
  │    → 死区时间占比翻倍（固定硬件死区 / 更短周期）
  │    → 有效输出电压损失增大
  │    → 高速电压裕量不足
  │         ↓
  │    高速电压饱和（反电动势 ≈ 母线电压）
  │    → 观测器电压估算失准（指令电压 ≠ 饱和后实际电压）
  │    → 转子角度估算误差
  │    → Park 变换不对齐 → q 轴扭矩电流投影到 d 轴
  │    → Id 反转变正（+0.34A = 增磁）← 关键证据
  │    → 反电动势增大 → 加剧电压饱和（正反馈）
  │    → Id 振荡增长 → 扭矩振荡 → 机械抖动
  │    → 转速上限被限在 ~2000rpm（电压饱和 + 失稳）
  │
  └─ 功率 0.4W → 4W（10 倍）
       → 额外功率 = 铜损（I²R）+ 振荡损耗
```

**现象 1（CPU 负载）**：32kHz 电流环每秒执行 32000 次，每次中断完成 ADC 采样→Clarke→Park→双 PID→反 Park→SVPWM→观测器→PLL。STM32F401RE 84MHz，55.2% 负载 ≈ 17.25μs/中断，剩余给中频任务（1kHz 速度环）和主循环。

**现象 2（转速上限降低）**：核心是**死区时间占比**。L6230 硬件死区固定（约 500ns 量级），PWM 周期减半（62.5μs→31.25μs），死区占比翻倍，有效电压损失增大。高速时反电动势接近 12V 母线，死区损失让电压裕量不足，弱磁也无法补偿，转速上限被限在 ~2000rpm（vs 16kHz 的 2502rpm 额定）。

**现象 3（边界失稳 + Id 方向反转）**：电压饱和后，观测器用指令电压估算转子角度（指令电压 ≠ 饱和后的实际电压），角度误差导致 Park 变换不对齐，q 轴扭矩电流投影到 d 轴。**Id 从 -0.11A 反转到 +0.34A**（方向反转 = 从弱磁变增磁），这是关键证据——不是弱磁"力气不够"，而是电压饱和引发**正反馈失稳**：+Id 增磁 → 反电动势增大 → 电压需求更高 → 加剧饱和 → 角度误差更大 → Id 继续增长。正反馈让 Id 振荡到 0.34A，功率从 0.4W 飙到 4W（10 倍），额外功率变成铜损（I²R）和振荡损耗。扭矩振荡的低频成分穿透机械结构，导致底座移动。

> Id 方向反转（-0.11A → +0.34A）是区分"弱磁不足"与"正反馈失稳"的决定性证据。若仅弱磁不足，Id 应保持负值且绝对值增大；方向反转为正说明控制环路已失稳，Id 脱离控制器约束。

**工程权衡启示**：

| PWM 频率 | 电流环带宽 | 嗡鸣声 | CPU 负载 | 死区损失 | 转速上限 | 失稳风险 |
|---|---|---|---|---|---|---|
| 8 kHz | 低 | 尖锐 | 低 | 小 | 正常 | 启动电流大 |
| 16 kHz | 中 | 微弱 | 中 | 中 | 2502 rpm | 低（平衡点） |
| 32 kHz | 高 | 几乎无 | 55.2% | 大 | ~2000 rpm | 高（电压饱和失稳） |

**结论**：16kHz 是本平台（STM32F401RE 84MHz + L6230 + 12V）的**最优平衡点**——电流环带宽够用、CPU 负载有余量、死区损失可控、高速电压裕量充足。ST 默认配置 16kHz 不是随意选择，是基于这些权衡的工程决策。频率提升不一定更好，存在"死区损失→电压裕量→饱和失稳"的反向边界。

### 8.3 实验五：32kHz + 过调制 → FOC 运行超时

**实验目的**：验证 32kHz 失稳是否为电压裕量问题——开启过调制扩展电压极限，看能否突破 2000rpm 且 Id 恢复负值。

**操作**：32kHz 下使能过调制（overModulation），启动电机。

**结果**：开环强拖阶段就报 **FOC 运行超时**（`MC_FOC_DURATION`）。转速仅 24 rpm，Iq=0.02A，功率 0W，电机根本没启动起来。

**根因：CPU 算力边界，非电压裕量**

32kHz 不开过调制时 CPU 负载 55.2%（≈17.25μs/中断，PWM 周期 31.25μs，裕量约 14μs）。开启过调制后，电流环增加过调制相关的非线性计算（调制比>1 时的六阶梯波注入），中断执行时间增长，**超过 PWM 周期 31.25μs → 触发 FOC 超时**。

55.2% 负载看似有裕量，但开过调制就溢出——说明 CPU 裕量其实很紧，只是恰好够跑基础 FOC。

**实验五的判别结论**

原预测的两个分支：
- 若过调制能突破 2000rpm 且 Id 恢复负值 → 证明根因是电压裕量
- 若过调制后仍失稳（Id 仍正）→ 说明观测器有根本缺陷

**实际结果开了第三个分支**：根本没到闭环，开环就超时了。既没验证电压裕量假设，也没触及观测器层——卡在了 CPU 算力边界。

**32kHz 失败机制全貌（双边界）**

| 边界 | 触发条件 | 现象 |
|---|---|---|
| CPU 算力边界 | 开过调制增加计算量 | 开环就 FOC 超时（24rpm） |
| 电压裕量边界 | 闭环高速域反电动势≈母线电压 | Id 反转正反馈失稳（~2000rpm） |

两个边界都指向同一结论：**32kHz 对本平台（STM32F401RE 84MHz + L6230 + 12V）太高了**。16kHz 在两个维度都有充足裕量，是其作为平衡点的深层原因。

### 8.4 实验三+四：额定转速改动 + 目标转速 600rpm（额定转速是观测器整定输入）

**实验背景**：为验证电压裕量假设（16kHz + 过调制能否突破 2502rpm 额定），将额定转速从 2502 改到 3000 以突破 Pilot 转速上限，同时把 `DEFAULT_TARGET_SPEED_RPM` 设为 600rpm。PWM 频率回到 16kHz。

**参数变化确认**（vs 16kHz 基线）：

| 参数 | 16kHz 基线 | 本次 | 变化原因 |
|---|---|---|---|
| `MAX_APPLICATION_SPEED_RPM` | 2502 | 3000 | 手动改额定转速 |
| `PWM_FREQUENCY` | 16000 | 16000 | 回 16kHz |
| `DEFAULT_TARGET_SPEED_RPM` | （默认） | 600 | 手动改 |
| `OBS_MINIMUM_SPEED_RPM` | 901 | 901 | 不变 |
| `GAIN2` | 26133 | **20906** | **Workbench 因额定转速重算** |
| `PLL_KP_GAIN` | 582 | **698** | **Workbench 因额定转速重算** |
| `PLL_KI_GAIN` | 26 | **31** | **Workbench 因额定转速重算** |
| `Phase2_FINAL_SPEED` | 1001 rpm | **600 rpm** | **DEFAULT_TARGET_SPEED_RPM 级联** |

**两个新的级联发现**：

- **发现 C（额定转速是观测器整定输入）**：`MAX_APPLICATION_SPEED_RPM → MAX_BEMF_VOLTAGE → GAIN2/PLL/C3` 重算。这是 PWM 频率之外的**第二条级联重算线**（额定转速→反电动势常数→观测器/PLL 增益）。
- **发现 D（DEFAULT_TARGET_SPEED_RPM 级联到 Phase2 强拖转速）**：启动序列 Phase2 的 `PHASE2_FINAL_SPEED` 从 1001rpm 变成 600rpm，与 `DEFAULT_TARGET_SPEED_RPM` 同步——默认目标转速不只影响稳态，还影响启动序列。

**实验 8.4a：过调制开 → 启动失败（震动顿挫）**

操作：16kHz + 额定3000 + 目标600 + 过调制使能，启动电机。

结果：开环强拖阶段报启动失败（`MC_START_UP`）。电机启动时震动厉害，有很强顿挫感。转速到 996rpm（接近 Phase3-5 的 1001rpm）后失败。CPU 负载 15.3%（16kHz 充裕，排除 CPU 边界）。

初步判断：过调制设计用于**高速弱磁区**（调制比>1），开环强拖从 0→600→1001rpm 调制比远小于 1（电压未饱和），过调制在低速激活导致调制器输出畸变电压矢量 → 扭矩脉动 → 震动顿挫 → 启动失败。

**实验 8.4b：过调制关 → 仍启动失败（锁定额定转速为根因）**

操作：关掉过调制，其余参数不变（16kHz + 额定3000 + 目标600），重测。

结果：依然启动失败。过调制不是根因（或不是唯一根因）。排除过调制后，**唯一变量锁定为额定转速 2502→3000**。

**根因：额定转速 3000 导致观测器增益失配**

电机物理特性没变（反电动势常数 3.31、Rs=3.19、Ls=0.8mH 都是 2502 电机的值），但 Workbench 以为这是"额定 3000rpm 的电机"，据此整定了错误的观测器增益（GAIN2/PLL/C3）。

失配机制：
- 观测器（STO）用 GAIN1/GAIN2/C1/C3/C5 估算转子角度
- 这些参数基于"虚假"的 3000rpm 反电动势整定
- 启动 Phase2 观测器运行（`ENABLE_SL_ALGO_FROM_PHASE=2`），参数失配→估算角度不准
- Phase5 切闭环时 SPEED_BAND 检查：估算转速 vs 强拖转速，偏差超容限→切闭环失败→`MC_START_UP`

**关键学习点：额定转速的双重角色**

额定转速不只是"转速上限"，它是 **Workbench 整定观测器的输入参数**——通过 `MAX_BEMF_VOLTAGE` 影响 `GAIN2/PLL/C3`。改额定转速 = 欺骗 Workbench，让它为不存在的电机特性整定观测器。

要突破 2502 转速上限，正确做法不是改额定转速，而是：
1. 额定转速保持 2502（电机物理值，观测器才正确）
2. 在高速域（接近 2502 时）靠弱磁 + 过调制扩展电压极限

但过调制如果是全局使能（不分速度区间），低速开就会出问题（8.4a 震动顿挫）——需研究 MCSDK 的过调制激活机制是否速度自适应。

**对比：32kHz vs 16kHz 开过调制**

| | 32kHz + 过调制 | 16kHz + 过调制 |
|---|---|---|
| CPU 负载 | 55.2% | 15.3% |
| 失败阶段 | 开环就 FOC 超时 | 开环跑到 ~996rpm 才启动失败 |
| 失败层 | CPU 算力边界 | 控制层（震动顿挫） |
| 能看到过调制对控制的影响 | 否（被 CPU 超时掩盖） | 是（干净观察场） |

16kHz 下 CPU 不再是瓶颈，第一次看到过调制对控制的实际影响。

## 九、反思

这次实验的价值不在"改了个参数电机还能转"，而在**看见了工具链的级联重算机制**——改一个值，背后有 4 层派生参数被自动调整，而且 Workbench 的重算范围比公式派生更深（主动整定观测器增益）。理解这套机制，是从"黑盒用工具"走向"懂工具在做什么"的关键一步。

故障排查的过程同样有教训：从相序到排针到代码参数，绕了一大圈，根因竟是电位器位置——一个最不起眼的配置项。说明调试时不要忽略"最简单的物理状态"，也不要轻信"之前以为无效"的判断。

额定转速改大的失败则揭示了另一层教训：Workbench 的参数不是都能随意改的——额定转速、PWM 频率这些"看似只是上限/配置"的参数，实际上是观测器整定的输入。改它们等于欺骗工具链，让观测器为不存在的电机特性工作。要突破物理极限（如转速上限），应该在运行时用弱磁+过调制等控制策略，而不是在配置时改电机参数。配置参数反映的是物理事实，不是愿望。
